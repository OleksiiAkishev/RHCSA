# Private IP addresses

Private IP addresses are used inside private networks and are not globally unique.

| Private block                   |  CIDR | Mask          | Host bits |  Total addresses | Traditional usable* |
| ------------------------------- | ----: | ------------- | --------: | ---------------: | ------------------: |
| `10.0.0.0 – 10.255.255.255`     |  `/8` | `255.0.0.0`   |        24 | 2²⁴ = 16,777,216 |          16,777,214 |
| `172.16.0.0 – 172.31.255.255`   | `/12` | `255.240.0.0` |        20 |  2²⁰ = 1,048,576 |           1,048,574 |
| `192.168.0.0 – 192.168.255.255` | `/16` | `255.255.0.0` |        16 |     2¹⁶ = 65,536 |              65,534 |


- Private range ≠ necessarily one network.
    From one big private network we can have many small subnets. Under /8 we can have /24 /21 /22, etc.
- The entire private address block reserved by RFC 1918 (RFC1918 is an Internet Engineering Task Force (IETF) standard that allows enterprise organizations to assign IP addresses to internal hosts)



# NAT (Network Addres Translation)
The private IP addresses cannot easily talk to the external world, the same the external world cannot reach private IP adddresses. Thus the NAT is used at the router level, in that case the IP address is replaced with the IP address of NAT router. And the nodes in the Internet they think they communicate with the NAT router and not with indivudual hosts. 

The NAT/state table records the mapping created by the outgoing connection, allowing the returning traffic to be associated with the correct VM.

# CIDR (Classless Inter-Domain Routing)
Tells which bits from IP address belong to host. 

CIDR notation: /24
classic notation: 255.255.255.0 

# MAC address
Each physical network card has the 12 hexadecimal digits, representing 6 bytes / 48 bits MAC address and uses it in the local network(LAN or WLAN).Just up to the first router that is encountered and they cannot be used between nodes which are on the different networks.
MAC example: 00:0c:29:7d:9b:17; first 6 bytes are vendor ID, and the other 6 bytes a node ID.

# ARP (Address Resolution Protocol)

ARP is used to discover the MAC address of a device on the local network — including the gateway when the final destination is on another network

# Why still need IP and MAC?
1. IP address
   ↓
   Identifies the logical destination
   and lets us determine:
   "Is it local or remote?"
   
2. IP + subnet mask
   ↓
   Determine whether destination
   belongs to the same network.

3. If LOCAL
   ↓
   ARP
   ↓
   Find destination's MAC address

4. Ethernet
   ↓
   Creates/transmits the local Ethernet frame
   using MAC addresses

5. Switch
   ↓
   Uses the destination MAC to
   deliver the frame to the correct port

Where:
IP address
→ logical/network addressing
→ routing
→ "Where is the destination?"

MAC address
→ local/link addressing
→ "Which interface gets this frame on this link?"

And Ethernet frame can be:
Ethernet frame
┌──────────────────────────────┐
│ Destination MAC              │ ← local delivery
│ Source MAC                   │
│                              │
│   IP packet                  │
│   ┌──────────────────────┐   │
│   │ Destination IP       │   │ ← logical destination
│   │ Source IP            │   │
│   └──────────────────────┘   │
└──────────────────────────────┘

Rule: IP tells us where the packet ultimately needs to go; MAC tells the local link where to deliver the current frame.

# Addresses and Interfaces

Why need interface? - Because the machine (physical/virtual) needs something through which it communicates with the network.

Interface can a physical and also a virtual like in VMs.

- Fixed IP addresses:
    for servers that always need to be available at the same IP address
- Dynamic assigned IP addresses
    for users devices and for cloud environment. Usually a DHCP (Dynamic Host Configuration Protocol) is used. 

Linux had the names for the network cards: eth0, eth1, eth2, etc. Where the the naming is assigned based on the order detection of the network card. So the eth0 is the first card and so on.

After RHEL 7:
- en Ethernet
- wl WLAN
- ww WWAN
- o onboard
- s hotplug slot
- p PCI location
- x device name based on the MAC address of the network card
- number followed for ID, port, index

Ex: eno16777734
